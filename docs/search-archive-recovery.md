# 搜索恢复与压缩包入库验收

## 本轮确认的问题

1. 为减少误匹配及耗时，旧多来源聚合被收缩为单一作品索引及近期50条公开帖子，检索范围确实下降。
2. 原来源中的电视剧/动漫大量改为ZIP、RAR、7Z或ISO。原程序只接受视频，因此不会展示它们。
3. 分享者封禁曾误判为当前账号认证失败，会中断其他来源。
4. 目录中增加标点、发布者前缀或同集多画质时，部分正常结果被过严规则隐藏。
5. 夸克分享目录错用了page/size参数，上游忽略后默认只返回前10条；程序再按100条判断最后一页，导致漏读、错误缺集。现已改为_page/_size，并按返回的分页大小与总数遍历全部原始分页。总数可能包含夸克不公开返回的文件，完整度只统计实际列表；重复页或达到遍历上限会报读取未完成。

本次恢复已真实验证可访问的免费 quark4k 公开论坛，与现有来源同轮并行查原片名。未恢复不稳定的广泛聚合，也不改词、不读旧搜索缓存。新增源返回空结果、失败和超时分别处理。

## 压缩包流程

搜索展示实际压缩包编号范围、已知目标范围内的缺集，以及“需解压核对”。按钮明确为“解压第N集”，当前操作只处理这一集。用户点击后：

1. 服务端重新按原片名查询，核对该分享仍属于所选作品、类别与已知年份。
2. 重新读取分享文件，核对所选档案FID与集号。
3. 验证现有认证、SVIP及容量。容量至少覆盖压缩包的3倍，未确认时不开始转存，不自动开通付费服务。
4. 单个压缩包保存到当前账号下的系统任务临时目录，提交夸克云解压。视频不下载到应用服务器。
5. 解压后读取实际视频并核对指定集号、季度、命名及新鲜发布信息。数字文件名只可用于已选定的单个档案；明确其他作品的文件拒绝入库。
6. 确认视频后移入当前用户的影片目录，保持原有文件与观看记录；重复请求复用同一任务。
7. 保存片库元数据后显示立即播放/查看片库；临时副本移至夸克回收站。清理失败不伪造失败或删除影片，界面提示清理待办。

现阶段每个任务只解压所展示的一集。普通搜索优先展示已核对视频；压缩包结果选取该来源实际可识别的最新一集，用户可输入“片名 第N集”指定集数。不会把一集任务宣传成全集。RAR/7Z走同一官方解压通道，但本次真实成功样本为ZIP。加密压缩包、异常档案或接口限制可能失败，保留临时文件和断点供检查。

ISO实测被夸克接口拒绝（bad archive file），当前不支持；不把ISO当作视频或默认为可解压。

压缩包来源不进入旧的直接追更/自动换源写流程，片库更新数字以实际已存视频为准。新增一集仍需通过解压核对，不以分享中的剧场版或旧集数覆盖进度。

## API与持久化

- GET /api/quark/archive-capabilities
- POST /api/library/archive-jobs
- GET /api/library/archive-jobs/:id

沿用应用登录、同源检查和用户隔离。任务按用户/片名/类别/分享/档案/集号确定标识，合并并发点击。全局最多2个任务；同一影片和目录继续使用现有写锁。

data/archive-jobs/保存私有断点，文件权限0600，不存网盘Cookie、分享密码或压缩包密码。成功结果仅返回必要的媒体记录；其他用户不能读取任务。服务重启后可按断点检查已有转存及解压任务；未确认提交时不自动重复提交。多个应用副本仍需由部署层确保单实例写入同一网盘，现有锁为进程内锁。

## 部署与依赖

需要更新前后端镜像并重建应用容器，保留原数据卷；无新增npm依赖或API密钥，不需要重装iPhone描述文件。正式服务器需可连接现有免费来源、quark4k.com及夸克官方接口。免费来源存在取消分享、限流和偶发超时，遇到失败显示“查询未完成”，不能承诺每次都有可用结果。尚未提交/推送本次变更时，正式站点仍运行旧代码。
