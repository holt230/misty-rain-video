# 内容首页与观影交互

本轮基于 main-master（7add5dd），开发分支 codex/tencent-style-ui。

## 功能与范围

- 手机四个主入口：首页、找片、片库、我的；桌面侧栏与同一套页面对应。
- 首页独立于个人片库，展示豆瓣热门剧集、电影、动漫、综艺与新片，展示来源和资料更新时间。电影接口中的明确电视剧条目会被过滤。
- 影片详情提供来源资料、评分和“找源并播放”。评分为空时不显示，不把来源的 playable 标记当成本应用的播放能力。
- 已入库作品通过 catalogId 或无歧义的标题/分类关联。未入库作品复用原搜索引擎；自动选择要求标题边界、年份、季数吻合，再读取分享目录验证。信息不足或验证失败时由用户选择。
- 用户点击找源并播放才会转存。查看首页和详情不会批量搜索或转存；准备期间可以切换到手动选择。
- 自动准备会在 30 秒调度窗口内检查最多 12 个不同候选，并等待迟到的搜索结果。失效或无法核对的分享继续检查下一个；认证/访问限制停止自动重试，保存失败也不会重复写入。核对结果提示不会再被后续搜索进度覆盖。
- 播放器全页展示，正序选集自动定位当前集，提供倒序、设置面板、倍速、临时长按加速、双击播放暂停和横屏锁定。设置/选集面板复用同一个视频实例。
- 找片支持个人搜索历史、片库匹配、热门目录匹配、分享链接导入。历史按用户名保存在当前浏览器；片库和观看进度继续使用既有账户隔离。
- 片库提供在看、有更新和排序；个人中心按历史、播放服务、外观和设备分组。
- 系统/浅色/暗色偏好保持兼容。网页不提供跨设备统一亮度手势、系统投屏或离线下载。

## 目录服务

登录后访问 GET /api/catalog?channel=tv|movie|anime|variety|new。

服务端优先读取豆瓣选片页公开使用的目录数据，失败时尝试旧的公开列表；日本动画回退会注明范围。无需新增 API Key。公开接口不保证持续可用，失败时使用上次成功快照。冷启动无快照且来源失败时显示重试和搜索入口。

快照有效期为 6 小时，过期读取立即返回旧内容并后台更新；失败重试间隔至少 1 分钟，并合并相同频道的并发请求。生产服务启动 5 秒后预热，并每 6 小时检查一次。开发模式按需读取。

前端在服务端仍更新时有界读取后续结果，完成后替换旧目录；退出登录或离开应用会取消后续调度。

数据位于持久化目录的 catalog/：
- 频道 JSON：热门目录快照及来源信息。
- works/：已发现作品的海报地址，保证保存到个人片库后不因退榜丢失海报。
- JPEG 缓存：限制单张大小，最多同时请求 4 张，过量缓存清理不在当前榜单中的图片。

海报接口只接受数字作品编号；远端地址来自目录，限制 HTTPS 豆瓣图片域名、禁止重定向、校验类型和文件头，不能作为任意 URL 代理。不向资料源发送本站或网盘凭据。

当前没有接入 TMDB Key 或新增独立 Bangumi 首页频道；两者可作为将来的目录适配器。现有海报服务仍保留原有来源。

## 验证与发布

类型检查使用 vue-tsc --noEmit。初次交付未进行完整构建；后续真实验收已使用 /misty-rain/ 基路径完成生产前端构建，Node 堆内存限制为 512MB，产物放在忽略的独立验收目录中。

浏览器验收分两类：
- 实际公开目录和海报：本机开发服务访问豆瓣返回的内容。
- 入库与播放器流程：独立测试账户、拦截的网盘响应和本地生成的 WebM 验收画面，不代表真实网盘转存或真机播放验收。

发布需要构建前端并更新运行代码；Docker 部署需要重建镜像并重建应用容器，保留原数据卷。现有数据没有破坏性迁移。新增服务依赖部署网络可访问豆瓣；资源检索和播放仍依赖既有检索服务与有效网盘认证。

2026-11-02 本地验证：类型检查通过，44 项定向用例通过；五个真实目录频道各返回 24 条内容。检查了 320px、390px 手机布局、1440px 桌面布局与浅色/暗色主题。隔离浏览器流程验证了自动匹配后入库播放第一集、换源后播放、取消后不继续入库、详情返回保留滚动位置、个人中心返回，以及设置/选集焦点和同一视频实例。未执行完整生产构建、真实网盘转存或真实手机验收。

## 2026-11-14 iPhone 播放状态栏与长按

- 进入网页横屏时，浏览器主题色、页面与安全区底色统一为黑色，退出、关闭或卸载播放器后恢复当前主题；不会把临时播放状态写入用户的主题偏好。
